# Stanford University Stage 1 draft

Institution ID: `stanford-university-usa-ca`. Inventory captured 2026-10-02; final research and owner review completed 2026-10-03. Status: Stage 1 reviewed. This directory is outside active runtime inputs.

The 2026-27 Bulletin inventory, external graduate application directory, current-student coterminal guidance and professional-school admissions are separate evidence sources. An undergraduate major is a post-admission study option, not a separate first-year application. A departmental master's award does not establish external terminal-master admission. Coterminal, intermediate, joint and restricted awards retain their actual relationship.

Evidence dossiers use `sources`, `study_options`, `application_procedures`, `facts`, `unresolved`, and `collection_tasks` arrays. Source records retain official URL/title and original checked date; access success does not mean content review. Facts carry ID, topic, paraphrased value, publication/review status, checked date, source IDs and explicit scope (options, procedures, levels, applicant categories, cycle and fee status). Conditions/exceptions stay with the fact. Research unknowns require reason, reviewed source evidence and official next step. Unsearched groups remain collection tasks.

Bounded workers own their named evidence dossier only. The institution owner serially assembles the canonical inventory, linked catalog, schema, filled example and coverage report; only the Stanford checklist line may change. Existing runtime evidence is preserved separately with its original dates rather than relabelled freshly verified. Shared policy applies only when its explicit scope intersects the selected context, never by shared portal or school membership alone.

Completion requires inventory reconciliation, application classification, researched applicant fact groups and direct draft validation. Runtime audit does not read these drafts and cannot establish their completeness. Integration, browser UX work and Git release operations belong outside this task.

The reviewed index contains 253 study options, 448 sourced application/progression contexts, 1,222 facts and 585 original source records (538 distinct URLs). It retains 62 current researched unknowns and six superseded historical collection notes. These counts include internal awards, named variants and repeated dossier views of shared applications; they are not counts of independent externally available degrees or admissions forms. ## Linked contract

`inventory-snapshot.json` preserves the public 2026-27 Bulletin display rows, including non-degree exclusions. Its configured university-hosted display uses public Coursedog metadata; the raw list is not proof that every restricted award is offered to a new applicant. Independently sourced offerings/configurations missing from the display remain in supplemental evidence rather than being discarded. `graduate-directory-snapshot.json` and `coterm-directory-snapshot.json` preserve exact named application tables. The separately labelled Stanford Bulletin link identifies the degree; a Program Website link can point to a related degree and must not override it.

`catalog.json` is a linked index. Resolve each fact's `evidence_file` and `original_id` for its complete value, conditions and exceptions. `original_scope`, source checked date and publication/review status preserve the dossier verbatim; the index normalizes explicitly known option and level aliases. Variant IDs and `parent_option_id` preserve specializations without inventing independent degrees. `application_classifications` keeps each evidence profile's classification rather than overwriting an earlier review. Differing classifications require a reasoned source review.

Source and procedure IDs are namespaced by dossier. Duplicated procedure names in different files do not prove the same application. Each option lists the researched procedure contexts and each procedure links back to its options. External nonprofessional directory contexts carry `shared_policy_context_ids` because the official directory explicitly points to central How to Apply; this bridge never transfers every central eligibility, fee, English or funding fact without its own conditions. Coterminal, internal and professional routes remain separate. Scope dimensions intersect; a fact with both option and procedure IDs belongs only to that option in that procedure.

`sources.json` retains the full original source records. HTTP/access state remains distinct from content review. `runtime-provenance.json` is historical input only; import date never refreshes a source review. `evidence_fingerprints` makes stale indexing detectable. `schema.json` documents the index, while `example.json` contains filled contrasts with resolved fact values for review. Neither activates runtime readers.
