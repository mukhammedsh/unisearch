# Normalized admissions backend snapshot

`catalog.json` is the resolved `admissions-storage-1.0` snapshot for the accepted MIT, Imperial College London, Stanford University and Nazarbayev University batch. The backend reads this file directly; it does not read research draft formats at request time. Its source values, conditions, scopes, statuses, dates, and evidence records follow [the storage contract](../../../docs/admissions-storage-contract.md).

`runtime_active: true` activates this accepted four-institution contract. Their `universities.json` rows contain common institution information and an `admissions_catalog_id` ownership reference; admission policies, study options and cost/funding facts come only from this snapshot. Ordinary detail, card/search, ranking and comparison consumers use its reviewed metadata and explicit selected context. The other 46 institutions retain their existing contract and are labelled as awaiting the detailed admissions review. Paused drafts remain inactive.

To refresh the snapshot after a reviewed draft update:

1. Run `backend/scripts/prepare_admissions_catalog.py` using the backend environment, with `--output-dir .tmp_test/admissions-refresh` pointing to a new directory. NU requires `packet-b/data-acceptance.json` matching the reviewed catalog hash and current packet/handoff fingerprints; source changes require renewed evidence acceptance.
2. Review the generated inactive snapshot and its input manifest. Change only its envelope's `runtime_active` value to `true`, then replace this directory's `catalog.json` with the validated result. The output also contains `nu-assessments.json`: replace only NU records in `assessments.json` with these reviewed source-hash mappings, preserving the other institutions. Do not copy program or policy records into `universities.json`. Preparation always emits inactive data; the runtime loader accepts only the activated contract.
3. Run `npm run test:backend -- test_admissions_catalog_preparation test_admissions_catalog test_admissions_assessment test_admissions_scoring_integration`, then the required backend/data checks.

The preparation test compares every stored entity with resolved accepted evidence while distinguishing inactive preparation from runtime activation. Input hashes identify the original bytes; source files checked out with different line endings can have different byte hashes without changing their JSON content. Backend cache revisions hash this snapshot's bytes, so an updated snapshot invalidates affected search and assessment caches, including unselected accepted contexts. Detail ETags hash the same representation returned to the client. Browser detail cache version 4 revalidates reviewed entries and does not substitute stale data when the reviewed catalog is unavailable.

The [retired records](../history/README.md) preserve the previous four complete university records as inactive, unreviewed history. They are not a second runtime reader. The legacy admissions synchronization script skips rows with the ownership reference; curated institution facts may still update common fields but must not recreate old academic acceptance-rate or admissions fields.

The full snapshot is storage, not a default HTTP response. Use the paginated study-options API and the selected-context API documented in [the runtime contract](../../../docs/admissions-runtime-contract.md). Sources and narrative conditions retain their publication/review state; unsupported conditions remain unassessed, and unknown annual costs are not replaced by tuition or assumed aid.

The retired Imperial Computing PhD representation included four dates labelled as 2027 departmental rounds. Do not restore that archived schedule or inherit MSc Computing rounds. The accepted `imperial-computing-phd-admission` source narrative separately retains April/October 2027 round-opening dates and corresponding decision dates; these are not inferred application-closing deadlines. Read them with the source's stated cycle and do not invent an exact closing time. Recheck the official PhD page before changing those facts.

`assessments.json` contains bounded, reviewed interpretations of specific published checks, not replacements for source facts. Each record identifies its institution, fact, canonical fact-content hash, explicit selection scope, supported checks and remaining conditions. `mapping_reviewed_at` dates the interpretation; it does not refresh the original fact's source review. Missing/corrupt mappings fail explicitly, and changed source content leaves its mapping unassessed until reviewed. Update affected mappings after a snapshot change and run `test_admissions_assessment`; never relax a condition or invent a threshold to restore a numeric result.
