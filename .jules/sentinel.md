## 2026-09-27 - Expanded Sensitive Header and Credential Scrubbing in Observability Events
**Vulnerability:** The observability data scrubber (`_scrub_sensitive`) checked a narrow set of substrings (`token`, `secret`, `password`, `authorization`). Headers and payload fields containing session identifiers or API keys (such as `Set-Cookie`, `X-Api-Key`, `Authentication`, `session_id`, `user_credentials`) were passed unscrubbed into error reports and telemetry events.
**Learning:** Observability event structures include HTTP headers and arbitrary nested JSON payloads. Relying only on exact key matches or a minimal keyword list leaves common credentials like cookies, session IDs, and custom API key headers exposed in external telemetry platforms like Sentry. Using overly broad substrings like `auth` can cause over-redaction of legitimate domain keys like `author`; specific keywords (`authentication`, `auth_token`, `auth_key`) must be used instead.
**Prevention:** Maintain specific keyword rules for all credential types in the central event scrubber, and write unit tests covering both request headers and nested payload fields without over-filtering domain fields.

## 2026-09-27 - ClusterFuzzLite Dockerfile Root Requirement
**Vulnerability:** Adding a `USER fuzzer` directive in `.clusterfuzzlite/Dockerfile` caused OSS-Fuzz compilation to fail with `Permission denied` when trying to write `/usr/lib/libFuzzingEngine.a`.
**Learning:** OSS-Fuzz / ClusterFuzzLite base images (`gcr.io/oss-fuzz-base/base-builder`) require root privileges during the fuzzer compilation step because the build environment writes system libraries (`libFuzzingEngine.a`) and dependencies.
**Prevention:** Do not add non-root `USER` instructions to ClusterFuzzLite Dockerfiles; the build environment expects root execution during image compilation.
